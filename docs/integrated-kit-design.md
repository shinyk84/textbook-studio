# 교과서 통합 제작 키트 설계안 (초안)

작성: 2026-10-28 · 상태: 검토용 초안

## 0. 목표

교과서 한 권의 제작 전 과정을 하나의 콘텐츠 원장 위에서 연결한다.

```
전처리 → 초안 생성 → 인디자인 조판 → [수정시안 → 수정조판] × N → 최종안 → 인쇄용 PDF
                                   ↘ 웹 지도서·학습도구 / 활동지·평가지·과정안 / 영상(롱폼·숏폼)
```

핵심 요구:

1. 한 곳을 고치면 영향을 받는 다른 산출물을 알려 준다(영향 알림).
2. 영향을 받은 산출물의 수정안을 만들고, 승인하면 반영한다(전파).
3. 학교급·과목·책마다 다른 분석·생성 방식을 수용한다(책 프로필).
4. 책 한 권 150~200쪽, 지도서는 그 이상의 분량을 처리한다.
5. 사내·외주 조판 모두 **일반 InDesign만으로** 작업할 수 있어야 한다(InDesign Server·유료 플러그인 불필요).

## 1. 설계 원칙

- **원문은 한 곳에만 둔다.** 교과서·지도서 문장은 콘텐츠 원장에만 있고, 다른 모든 산출물은 원장에서 생성하거나 원장을 참조한다. JS 파일·엑셀·인디자인 안에 원문을 직접 입력하지 않는다.
- **ID는 바뀌지 않는다.** 순서 변경·단원 이동에도 유지되는 불변 ID를 쓰고, `2단원 > 농구형 게임 > 활동 1` 같은 경로는 화면 표시용으로만 계산한다.
- **자동 수정, 사람 승인.** 검정 교과서이므로 AI·규칙이 만든 수정안은 편집자가 승인한 뒤에만 반영한다.
- **쪽 번호는 계산값이다.** "교과서 64~65쪽" 같은 참조는 조판본에서 회수한 쪽 대응표로 자동 계산하고 손으로 입력하지 않는다.
- **표준 형식만 쓴다.** 인디자인과는 IDML·ICML·ExtendScript(.jsx)·PDF 프리셋(.joboptions)·스타일 이름으로만 주고받는다.

## 4. L0 책 프로필과 전처리

학교급·과목·학년·검정/인정에 따라 분석·생성 방식이 다르므로, 공통 엔진에 **책 프로필**을 끼워 넣는 구조로 한다. 기존 `ANALYSIS_RULES.md`의 3등급 규칙(불변·편집 가능·참고 패턴)을 프로필의 뼈대로 쓴다.

### 4-1. 책 프로필 항목

| 항목 | 예: 초등 체육 5 | 예: 고등 스포츠 문화 |
|---|---|---|
| 근거 자료 목록 | 교육과정, 편찬상 유의점·검정기준, 타사 교과서·지도서 | 교육과정, 인정기준, 4개사 교과서·지도서 |
| 구조 단위 | 영역 → 단원 → 차시(활동 1·2) | 대단원 → 중단원 → 소단원 |
| 펼침면·코너 유형 | 활동형 펼침면, 안전·평가 코너 | 탐구·직접 참여·창작·진로 등 |
| 분량 규칙 | 학년별 차시·쪽수 | 32회, 본문 176쪽 + 부록 |
| 분석 규칙 세트 | 성취기준 분해, 학년 배분 | 소단원 근거 매칭, 종목 적용 |
| 생성 템플릿 | 프롬프트·스키마 | 프롬프트·스키마 |
| 스타일 계약서 | 인디자인 단락·문자·개체 스타일 이름표 | 〃 |
| 지도서 체제 | 차시별 지도 흐름·발문·평가 | 〃 |

### 4-2. 전처리 파이프라인

공통 단계는 같고, 단계별 규칙만 프로필이 바꾼다.

1. **수집**: 원본 파일 등록과 SHA-256 기록(기존 `sync_official_data.py` 방식).
2. **추출**: 텍스트 추출, 필요하면 OCR(기존 `preprocess_*`, `ocr_fallback_reprocess.py` 재사용).
3. **구조화**: 쪽 → 단원·차시·활동 경계 인식. 이 단계의 분할 규칙이 프로필마다 다르다.
4. **정규화**: 공통 스키마(근거 청크 + 위치 + 출처)로 저장한다.
5. **검수**: 사람이 경계와 오인식을 확인하고 승인한다.

### 4-3. 자사 기존본 역수입

이미 출판된 책을 수정하는 경우(예: 5학년 체육) 기존본을 원장으로 바꾸는 경로가 필요하다.

- **IDML이 있으면(권장)**: 프레임·스토리·스타일·쪽 위치를 그대로 읽어 요소로 만든다. 정확도가 가장 높다.
- **PDF만 있으면**: 텍스트 좌표와 글자 크기로 블록을 나누고 사람이 검수한다. 시간이 더 든다.

## 5. L1 콘텐츠 원장

### 5-1. 계층

`책(Book) › 대단원(Part) › 단원(Unit) › 차시(Lesson) › 펼침면(Spread) › 요소(Element)`

교과서와 지도서는 별도의 책으로 두고, 지도서 요소가 교과서 요소를 연결로 참조한다.

### 5-2. 요소 유형

제목, 문단, 활동, 활동 단계, 발문, 구성요소 박스(코너), 삽화·사진(발주 설명 포함), 캡션, 표, 평가 문항, 성취기준 참조, 용어.

### 5-3. 핵심 테이블(개념)

| 테이블 | 주요 필드 |
|---|---|
| `element` | `id`(불변, 예: `e7K2QX9`), `book_id`, `parent_id`, `order`, `type`, `style_key`, `current_rev` |
| `element_rev` | `element_id`, `rev`, `content`(구조화 JSON), `author`, `round_id`, `reason`, `created_at` |
| `link` | `target_id`, `source_id`, `source_rev`, `relation`(copy·derived·refers·explains), `policy`(auto·suggest·notify) |
| `round` | `book_id`, `no`, `kind`(초안·1차 조판·1차 수정 …), `status` |
| `page_map` | `round_id`, `element_id`, `page_no`, `printed_page`, `frame_label` |
| `feedback` | 의견 원문, 출처(현장만족도·내부교정·심사), 연결 요소, 처리 상태 |
| `change_request` | 수정 제안: 대상 요소, 현재 문구, 수정안, 근거 의견, 상태(제안·채택·보류·기각·반영완료) |
| `asset` | 이미지·영상·move planner 시퀀스 등 파일 참조(본문은 파일 저장소, DB에는 경로만) |

## 6. 파생 연결과 영향 분석

### 6-1. 영향 알림

원장 요소의 `current_rev`가 바뀌면, 그 요소를 `link.source_id`로 가진 모든 대상 중 `source_rev`가 현재와 다른 것을 **갱신 필요** 상태로 표시한다. 연결을 따라 여러 단계로 전파한다(교과서 문장 → 지도서 카드 → 활동지 문항 → 숏폼 대본).

영향 목록 예:

```
[변경] 교과서 > 농구형 게임 > 활동 1 > 드리블 요점 문단 (rev 3 → 4)
  ├ 지도서 > 23~24차시 > 지도 카드 "드리블"            derived  → 수정안 생성
  ├ 웹 지도서 데이터 > bball-skill.guide.tips          copy     → 자동 반영
  ├ 활동지 > 23차시 > 문항 3                           derived  → 수정안 생성
  ├ 숏폼 대본 > 드리블 요점 30초 > 장면 2               derived  → 수정안 생성
  └ 인디자인 > 1차 수정조판 > 66쪽 프레임 e7K2QX9       copy     → 수정 패키지에 포함
```

### 6-2. 전파 정책

| 관계 | 의미 | 기본 정책 |
|---|---|---|
| copy | 원문을 그대로 씀 | 자동 반영 |
| refers | 쪽 번호·차시 번호 참조 | 쪽 대응표로 자동 계산 |
| derived | 요약·재서술·문항화 | AI 수정안 → 승인 |
| explains | 지도서 해설 | 알림 + 선택적 수정안 |

## 7. 인디자인 연동 (일반 InDesign 호환)

### 7-1. 제약과 선택

- InDesign Server, 유료 플러그인, UXP 전용 기능은 쓰지 않는다.
- 쓰는 것:
  - **IDML**: 구버전 InDesign에서도 열린다. 서버는 Python으로 IDML(zip + XML)을 직접 읽고 쓴다.
  - **ICML**: 스토리 단위 파일. 인디자인에서 '가져오기'로 배치하면 링크로 연결된다.
  - **ExtendScript(.jsx)**: 오래된 버전부터 최신 버전까지 스크립트 패널에서 실행된다. 외주 업체에도 파일 하나로 전달할 수 있다.
  - **.joboptions**: 인쇄용 PDF 프리셋.
- 최소 지원 InDesign 버전은 외주 업체와 합의해 프로필에 기록한다.

### 7-2. 스타일 계약서

책 프로필마다 단락·문자·개체 스타일 이름표와 템플릿(.indt)을 고정한다. 원장의 `style_key`가 이 이름에 1:1로 대응한다. 조판자가 스타일을 새로 만들면 회수 시 경고한다.

### 7-3. ID 보존 방식

- 기본: 텍스트 프레임·그래픽 프레임의 **스크립트 레이블**에 요소(또는 스토리) ID를 넣는다.
- 문단 단위: 스토리 안 문단은 순서와 텍스트 유사도로 대응시킨다.
- 대안(파일럿에서 비교): ICML의 XML 태그로 문단마다 ID를 넣는 방식. 조판 중 태그 손실률을 실측해 결정한다.
- `ID 점검.jsx`: 조판본을 넘기기 전에 누락·중복 ID와 계약서에 없는 스타일을 검사하는 스크립트를 사내·외주에 함께 배포한다.

### 7-4. 흐름

1. **초안 → 조판 패키지**: 단원별 폴더에 ICML(스토리별), 삽화 발주 목록, 템플릿, `배치.jsx`(템플릿에 스토리를 흘려 넣고 레이블 부여), 조판 지시 PDF를 넣는다. 스크립트를 쓰지 않는 업체는 ICML을 수동으로 배치해도 된다.
2. **조판본 회수**: 조판자는 INDD와 함께 **IDML 내보내기 + PDF**를 보낸다. 서버가 IDML을 읽어 다음을 처리한다.
   - 쪽 대응표(`page_map`) 생성
   - 조판 중 바뀐 문장을 원장과 비교해 "조판 중 변경" 목록으로 표시하고, 편집자 승인 후 원장에 반영
   - 넘침 텍스트, 스타일 위반, ID 누락 보고
3. **수정조판 패키지**: 승인된 수정안을 묶어 다음 세 가지를 만든다.
   - `수정반영.jsx`: ID로 프레임을 찾아 문구를 교체하고, 바뀐 부분에 색을 표시하며, 넘침이 생긴 프레임 목록을 남긴다.
   - 수정 지시 PDF: 조판 PDF에 주석으로 수정 위치·내용을 표시한다(사람용, 스크립트를 못 쓰는 경우의 대체 수단).
   - 수정 목록 xlsx: 기존 수정이력대장 형식을 이어받는다.
4. **반복**: 회수 → 의견 → 수정안 → 패키지를 N회 반복한다. 회차마다 원장 스냅숏과 PDF를 보관한다.
5. **최종 인쇄 PDF**: 프로필의 `.joboptions`(예: PDF/X-4, 215×280mm, 도련 3mm)로 내보낸다. `최종출력.jsx`가 대단원별 문서를 일괄 출력하도록 할 수 있다. 서버는 받은 PDF를 프리플라이트(폰트 포함, 이미지 해상도, 도련, 쪽수, 원장 대비 최종 문구 일치)로 검사한다.

## 8. 수정 회차 (N회 반복)

기존 수정시안 생성기의 로직(의견 카드 파싱, 쟁점 묶기, 보수·창의 모드, A/B안, 이전 제안 중복 방지)은 유지하고 입출력만 바꾼다.

| 구분 | 현재 | 통합 후 |
|---|---|---|
| 입력 | PDF 텍스트, 쪽 번호 | 원장 요소 + 쪽 대응표 + 조판 PDF(이미지용) |
| 위치 | `p`, 자유 문장 `location` | `element_id`(쪽은 계산값) |
| 출력 | HTML 보고서, PNG, xlsx | `change_request` 레코드 → 수정 패키지, 보고서·xlsx는 내보내기 |
| 상태 | xlsx 상태 열 | 원장 상태 + xlsx 동기 내보내기 |
| 반영 점검 | 다음 PDF 비교 | 다음 회차 IDML 회수 시 요소 단위 자동 확인 |

의견 출처는 현장만족도 외에 내부 교정, 심사 의견, 교사 검토를 같은 `feedback` 구조로 받는다.

## 9. 보조자료 모듈

- **웹 지도서 + 학습도구**: `*-data.js` 직접 입력을 없애고, 원장에서 JSON을 빌드해 배포한다. 온라인도구 지도서와 디지털 지도서는 하나로 합친다. 챗봇·전략판·점수판·활동지 제출 같은 도구 기능은 유지하고, 도구 안의 단원·차시 정보만 원장 ID를 참조한다.
- **활동지·평가지·과정안**: 차시 요소(성취기준, 종목, 준비물, 활동)를 입력으로 생성하고, 결과를 원장 링크로 등록한다. 과정안은 스튜디오의 HWPX 출력(`hwpx_export.build_hwpx`)을 재사용한다. 활동 생성기는 이 모듈의 대체 활동 생성 기능으로 흡수한다.
- **영상**
  - 롱폼·숏폼 대본과 장면 구성표는 원장에서 자동 생성하고, 링크로 연결해 교과서 변경 시 갱신 알림을 받는다.
  - 렌더링: move planner의 MP4/WebM 녹화, 이미지·TTS·자막 템플릿 조합 렌더러(후속 과제). 실사 촬영은 사람이 한다.
  - move planner 시퀀스 JSON은 표현 영역 차시의 `asset`으로 연결한다.

## 10. 분량 대응 (책 150~200쪽, 지도서 그 이상)

추정 규모(책 1권 기준): 교과서 요소 3,000~5,000개, 지도서 요소 10,000개 이상, 연결 수만 개, 회차당 IDML 대단원 4~8개.

- **저장**: Postgres를 기본으로 한다(스튜디오에 이전 스크립트 있음). 브라우저 저장소·JS 파일·xlsx를 원본 저장소로 쓰지 않는다.
- **이미지**: 파일 저장소에 두고 DB에는 경로만 둔다. dataURL을 JSON에 넣지 않는다(현재 수정시안 진행 파일이 과목 하나에 14MB).
- **AI 작업**: 단원 단위 작업 큐, 결과 캐시, 중단 후 재개. 변경된 요소와 그 파생물만 다시 생성한다(증분 생성).
- **인디자인**: 대단원별 문서 + InDesign 책 파일(.indb). 회수와 패키지도 대단원 단위로 처리한다.
- **화면**: 단원·펼침면 단위로 나눠 불러오고, 영향 목록은 산출물별로 묶어 접는다.
- **검증**: 파일럿 직후 5학년 교과서·지도서 전체를 역수입해 처리 시간과 비용을 측정한 뒤 신규 개발(초등 3·4, 5·6)에 들어간다.

## 11. 플랫폼

- 권장: **새 통합 코어**(Python 백엔드 + Postgres + 작업 큐)를 만들고, 기존 도구는 모듈로 옮긴다.
  - 스튜디오에서 가져올 것: 공식자료 전처리 스크립트와 `official-data`, 분석 규칙, 근거 인덱스, 초안 생성 프롬프트·스키마, HWPX 출력, 로그인·승인 구조.
  - 수정시안 생성기에서 가져올 것: 의견 파싱, 쟁점 묶기, 시안 생성 프롬프트, 대장 형식.
  - 온라인도구·디지털 지도서에서 가져올 것: 화면과 학습도구 전체(데이터 공급만 교체).
- 스튜디오의 1~9단계 화면은 코어가 자리 잡을 때까지 그대로 운영하고, 단계별로 옮긴다.

## 12. 파일럿: 5학년 농구형 게임 (교과서 64~69쪽 + 지도서 해당 차시)

선정 이유: 수정시안 생성기(5학년 PDF·현장 의견), 온라인도구, 디지털 지도서에 모두 이미 들어 있어 영향 알림·전파를 실제로 검증할 수 있다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P0 | 결정·자료 확보: 원본 INDD/IDML, 최소 InDesign 버전, 스타일 이름 목록 | 계약서 초안 |
| P1 | 원장 스키마 구현, 64~69쪽 역수입, 두 지도서 데이터 병합 | 원장에서 교과서·지도서 해당 범위 전체 재현 |
| P2 | 원장 → 웹 지도서 JSON 빌드, 온라인도구가 이 JSON을 읽게 변경 | 직접 입력 데이터 0 |
| P3 | 영향 알림·전파 화면 | 문장 1개 수정 시 영향 목록 정확, 승인 후 반영 |
| P4 | 인디자인 왕복: ICML·jsx 패키지, IDML 회수, 쪽 대응표 | 사내 1회 + 외주 1회 왕복 성공, ID 손실률 측정 |
| P5 | 수정시안 생성기 연결, 수정조판 1회 실제 수행 | 의견 → 수정안 → `수정반영.jsx` → 회수 확인까지 |
| P6 | 활동지·평가지·과정안·영상 대본 생성과 링크 | 교과서 수정 시 4종 모두 갱신 알림 |
| P7 | 5학년 전권 역수입 규모 시험 | 처리 시간·비용 기록, 병목 개선 |

## 13. 미결정 사항

- 텍스트북 스튜디오에서 아쉬운 점(화면 흐름, 구조, 속도 등) — 새 코어 화면 설계에 반영
- 5학년 체육 원본 INDD/IDML 확보 여부
- 사내·외주 InDesign 최소 버전, 외주 업체의 스크립트 실행 가능 여부
- 문단 단위 ID 방식(스크립트 레이블 + 매칭 vs ICML XML 태그) — P4에서 실측 후 결정
- AI 공급자(현재 모두 OpenAI) 유지 여부와 키 관리 위치
- 영상 렌더링 범위(대본·스토리보드까지인지, 자동 렌더링까지인지)
